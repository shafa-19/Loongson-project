The `example_7_2.zip` that came with the course material contains only empty
directories plus a stub `Build/subdir.mk`; the `.lxp` project file, `bsp_start.S`,
`main.c` and the `include/` / `core/` trees are missing.  Two options:

1. **Ask the instructor for the real archive** (best --- the startup code is board

   the whole `include/core` tree; then paste the block from
   `snippet_bsp_start.S` into `bsp_start.S`.

## Verified result

```
python verify_mips32.py
   t0 = 0xFFFE0001   (4294836225)   sum
   t1 = 0x0001FFFF   (131071)       next odd term, causes the wrap
   t2 = 0xFFFFFFFF   (-1)           0xFFFFFFFF, max unsigned 32-bit
   t3 = 0x0001FFFD   (131069)       last accepted odd term
   t5 = 0x80030000                  destination address
   mem[0x80030000] = 0xFFFE0001
verification : PASS
```

Number of accepted terms: `n = 65535`, and indeed `n^2 = 65535^2 = 4294836225 = 0xFFFE0001`.
The next term `131071` needs `131070` units of free space while only
`0xFFFFFFFF - 0xFFFE0001 = 0x1FFFE = 131070` ... `131071 > 131070`, so the loop
stops exactly one term before the unsigned overflow --- the guard is tight.

## Why the guard is correct

`subu t4, t2, t0` computes `MAX - sum` in 32-bit arithmetic; since `sum <= MAX`
the result is exact, so `t4` really is the number of units still free.
`bltu` (unsigned compare) then answers "would adding this term wrap?" without
needing the carry flag, which MIPS does not provide.
